# Subscription sign-in

Interactive runs support OpenAI Sign in with ChatGPT and xAI device-code sign-in. Choose a provider first, then run `/login oauth` or `/login oauth openai` / `/login oauth xai`. OpenAI opens a browser and receives the authorization response on a temporary `127.0.0.1` callback. xAI prints a verification URL and one-time code. `/logout` revokes the saved renewable credential when the provider exposes a revocation endpoint, then removes the local OAuth record.

Subscription credentials live in `~/.chivgent/oauth.json`, separate from API keys, with owner-only permissions and atomic replacement. The host identifier is stored in `oauth-host-id`. OAuth uses refresh-token rotation before requests and retains the latest returned refresh token. A file lock serializes updates across chivgent processes; if a process crashes while holding the lock, the next attempt stops safely and reports the lock path so it can be removed after confirming no process is using it. `OPENAI_API_KEY`, `XAI_API_KEY`, and `--api-key` continue to take precedence during normal startup; explicitly running `/login oauth` selects the subscription client for the current session. Provider/model switches preserve that explicit choice. A custom xAI endpoint cannot receive an xAI subscription token.

OpenAI follows the current [Sign in with ChatGPT open-source sign-in guide](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [account and session guide](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), and [models and inference guide](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference). This uses dynamic client registration, PKCE, OIDC ID-token verification against the discovery document's JWKS URI, and the granted `chatgpt.tokens.use.direct` scope. Inference uses the public `https://api.openai.com/v1/responses` endpoint, `store: false`, and streaming even for the non-streaming agent path; tool calls replay the transcript instead of depending on a stored `previous_response_id`. It waits for `response.completed`. The design deliberately does not use ChatGPT's private `backend-api` endpoints described in earlier issue assumptions.

xAI device authorization and token endpoints are checked against `https://auth.x.ai/.well-known/openid-configuration` at runtime. As of 2026-10-17, that metadata advertises RFC 8628 device authorization, token and revocation endpoints, and the `grok-cli:access` / `api:access` scopes. The public Grok CLI OAuth client ID is not in discovery metadata; the implementation follows the current [OpenCode xAI OAuth plugin](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/plugin/xai.ts) as a third-party reference. xAI has not published a stable client ID in its public docs, so this choice may need updating if that client changes.

Tokens are never printed or included in errors. Sign-in requests have bounded timeouts, state validation, cancellation, and explicit handling for denial, expiration, pending approval, and throttling. This implementation is covered by mock tests; it does not perform real sign-ins or paid inference as part of development checks.

Subscription usage is governed by the signed-in account's eligibility, available models, and provider limits. It does not grant unlimited usage or convert API-key requests into subscription requests. API keys continue to use the provider's API billing. OpenAI sign-in fetches the account's current model catalog and selects an available model if the current one is absent. On a later launch, use `--model MODEL` (or `/model MODEL`) to select the same model; no model entitlement is inferred from the subscription name. For xAI, set `XAI_MODEL` or `/model MODEL` before login.

Credential updates and refreshes serialize across processes using an owner-only lock file. If a process crashes while holding the lock, later operations fail after a bounded wait and identify the lock path. Remove that lock only after confirming no chivgent process is using the credential file. Never delete `oauth.json` as a substitute for releasing a stale lock.

Before declaring a provider's live integration verified, manually sign in, complete a model turn with a read-only tool, cancel another turn, restart and reuse the credential, then sign out. Automated tests cover these protocol paths with fake tokens; a real subscription account has not been exercised in this change. A failed remote revocation is reported separately from local logout.
