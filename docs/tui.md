# 滚动式 TUI

本地交互终端默认使用 rich TUI。启动实际会话：

```sh
npm run build
node dist/cli.js
```

用 `--simple` 强制使用追加式界面，或用 `--tui` 显式请求 rich TUI。自动选择要求
stdin、stdout 和 stderr 都是终端；管道、JSON、单次提问、`--serve` 和 `--connect` 保持简单输出。
`TERM=dumb` 自动使用简单界面。设置 `NO_COLOR` 不会关闭 rich TUI，只会禁用颜色。显式
`--tui` 要求 stdin 和 stderr 是终端，仍可将最终回答重定向到 stdout；`TERM=dumb` 下会明确报错。

没有 API Key 时输入 `/provider` 选供应商，然后直接输入 Key。也可运行离线演示：

```sh
npm run demo:tui
```

演示使用相同的 AgentSession、REPL 和实时区域，模拟流式回答和工具进度，不联网、不写工作区。

## 操作

| 操作 | 行为 |
| --- | --- |
| 输入问题，Enter | 发起一轮对话 |
| Ctrl+O | 在默认编辑器中插入换行；Enter 发送整段草稿 |
| 多行粘贴 | 作为一段完整问题插入，可继续编辑后发送 |
| 输入 `/` | 在当前输入行下方显示命令菜单；继续在 `/` 后输入以筛选 |
| 命令菜单中 ↑↓ | 遍历全部匹配命令，当前选中项保持可见 |
| 命令菜单中 Tab / Enter | 将选中项补全到草稿，再按 Enter 提交；完整输入的命令仍可直接执行 |
| 命令菜单中鼠标单击 / 滚轮 | 单击补全可见命令，滚轮在菜单上浏览候选项 |
| 滚轮向上滚过记录区 | 把滚轮交还终端，滚动原生滚动历史；下一次按键时恢复输入框的鼠标跟踪 |
| 命令菜单中 Esc | 关闭菜单，保留草稿 |
| 空闲输入时上下键 | readline 输入历史 |
| Ctrl+C（运行中） | 取消当前运行，保留已收到的文字，回到提示符 |
| Ctrl+C（空闲） | 清除当前草稿并回到输入框；空草稿时 Ctrl+D 退出会话，退出码 0 |
| Ctrl+A / Ctrl+E | 移动到行首 / 行尾 |
| Ctrl+D（空行）、`/exit` | 以退出码 0 离开会话 |
| `/status` | 会话状态、工作目录、轮次、消息数、Token 统计与权限模式（兼容 `/session`） |
| `/diff` | 经单次确认后交互式审查工作区 Git 改动；`/diff patch` 查阅最后一次应用补丁 |
| `/provider` | 打开供应商交互选择器；选中后若缺 Key，直接进入隐藏输入 |
| `/provider deepseek` | 在当前会话切换到 DeepSeek，保留对话历史 |
| `/model MODEL` | 切换当前供应商的模型 |
| `/endpoint URL` | 为 OpenAI 兼容供应商设置 API 地址 |
| `/login`、`/login deepseek` | 先选择供应商再保存其 API Key（不回显）；`/login deepseek` 跳过选择；`/login logout` 登出订阅 |
| `/permissions` | 查看或更改权限模式（`ask-first` / `workspace` / `unrestricted` / `plan`） |
| `/help` | 命令与快捷键帮助 |
| `/clear` | 清空模型会话内容，保留终端滚动历史 |
欢迎区保持两到三行。第一行是品牌和版本，第二行只显示工作区路径：放得下就显示完整路径，放不下就保留末尾，不会收成 `~`。只有需要设置供应商、模型或端点时才多显示一条操作提示。欢迎区不显示供应商和模型。会话标识按需通过 `/session` 或 `/status` 查看，欢迎区以及 `/new`、`/resume` 的成功提示不重复显示 session ID；`/resume` 的候选列表仍显示 ID，方便选择会话。

默认输入框用方框包住草稿，`›` 标出当前行。草稿为空时框内显示 Ask chivgent to do anything；这几个字不是草稿，回车不会发送。命令菜单显示在框下方。框外是一行安静的状态栏。左侧是当前供应商和模型，两者都已设置才显示，缺模型时不编造名字。同一行放得下时，后面是当前 Plan、Auto mode 或 Ask for me、Shift+Tab 的下一种模式和 `/help`。窗口较窄、模型名很长时，仍保留这段模式提示。Shift+Tab 只在空闲输入时切换；完整按键说明放在 `/help`。选择文字或打开命令菜单时，状态栏改为对应提示，暂不显示模型。占位符只在终端允许颜色时变暗。

运行区显示回答尾部、最多三个工具的最新进度、
轮次、耗时及 token。运行完成、取消、失败或达到轮次上限时会留下结果；`tokens+` 表示有一轮
未报告用量。长的单行回答会显示最新文字，长路径保留末尾文件名和工具进度；窄窗口优先
显示运行状态与停止快捷键。普通按键在运行中被丢弃，不回显，也不排队发送为下一条问题。
默认 rich TUI 使用可编辑的多行草稿；Enter 发送，Ctrl+O 插入换行，多行粘贴会保留为完整草稿。
`--simple` 使用单行输入：输入批次中的首个换行提交问题，后续内容被丢弃。请等待提示符重新出现再发送下一条。

切换供应商不会清空当前对话。新供应商没有默认模型时，用 `/model MODEL` 设置；
自定义 OpenAI 兼容端点还需 `/endpoint URL`。TUI 在选择缺 Key 的供应商后会立即询问 Key，
可先保存 Key，再补模型和地址；已有 Key 则跳过。`/login` 用于之后更换 Key：先列出供应商供选择，Esc 取消且不改动当前供应商。
`--api-key` 只用于启动时选择的供应商，不会误用到之后切换的供应商。
Key 写入用户的 `auth.json`，不同供应商各用自己的条目。
从 OpenAI 在会话内切换到自定义兼容端点时，也不会把 `OPENAI_API_KEY` 当作新端点的 Key；
切换到该端点时会单独询问它的 Key。

TUI 保留正常屏幕与终端原生滚动历史。提示符、进度和结果摘要写入 stderr，最终回答写入
stdout，支持 `node dist/cli.js --tui > answers.txt`。显式 `--tui` 在非 TTY 或非交互式调用时
仍明确报错；默认的管道和 JSON 调用继续使用原有渲染器。

## 终端适配

使用 `string-width` 与 `Intl.Segmenter` 按显示列和完整字符簇截断中文、组合字符及 Emoji。
运行区预留末列以避免自动换行；矮窗口优先保留状态。缩放时根据旧内容重排后的行数清除
原区域，再重画；清理范围限制在当前可见高度，避免极矮窗口把新状态滚出屏幕。
不同终端对 Emoji 宽度和历史重排的实现仍可能存在差异。

默认编辑器由 TUI 输入适配层接管；它独立解码按键，让多行粘贴和逐字输入走同一编辑路径，保持
折行和插入位置正确。简单模式由 readline 编辑。运行中仅转发 Ctrl+C；原始 stdin 不暂停，
因此取消不会被吞掉。退出或异常时会移除输入监听并恢复终端模式。运行环境要求 Node.js 22 或更新版本。

## 验证

```sh
npm run check
TMPDIR=/private/tmp npm test  # macOS 使用短路径，远程测试需要本地 socket 权限
npm run build
npm run demo:tui
```

自动测试覆盖显示列宽、字符簇、控制字符、欢迎面板、命令补全、输入隔离、取消后继续提问、
退出恢复、输出分流、失败提示和缩放清除旧行。`tests/tui-screen.test.ts` 使用 xterm 终端
解析器检查执行控制码后的屏幕内容，覆盖长中文粘贴、光标中间插入、草稿取消、EOF 清理、
快速多行提交，以及 80×24→32×12 / 16×5→120×40 缩放并保留历史。
真实 PTY 另验证 80→32→80 列缩放、流式工具、
Ctrl+C、再次提问、会话命令、Ctrl+D 和重定向 stdout。
